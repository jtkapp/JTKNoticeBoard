# JTKNoticeBoard

# 📢 सूचना बक्स — GitHub बाट चलाउने पूरा गाइड (म्याद + बि.सं., v3)

यो गाइडले एप अपडेट नगरी गृहपृष्ठको **सूचना बक्स** ON/OFF गर्ने, त्यसमा **text, तस्बिर, PDF** राख्ने, र **म्याद (expiry)** तोक्ने तरिका सुरुदेखि सिकाउँछ।

---

## 🧭 सारांश (एक नजरमा)

| कुरा | कहाँ हुन्छ |
|---|---|
| सूचनाको सामग्री, ON/OFF र म्याद | GitHub को `notice.json` फाइल |
| तस्बिर / PDF | उही GitHub repo मा |
| एपमा गर्नुपर्ने काम | `NoticeBoard.kt` मा `REMOTE_URL` **एकपटक** राख्ने |
| पछि सूचना बदल्न | GitHub मा `notice.json` सम्पादन गर्ने (एप अपडेट चाहिँदैन) |

**म्याद:** `from` / `until` ले सूचना कहिलेदेखि कहिलेसम्म देखाउने भन्ने तोक्छ, **बि.सं. र अङ्ग्रेजी (AD) दुवै मितिमा**। म्याद नाघेपछि एपले आफैं लुकाउँछ। हरेक सूचनामा छुट्टै `"enabled": false` पनि राख्न मिल्छ।

---

## भाग १ — एकपटक गर्ने तयारी (पहिलो पटक मात्र)

### चरण १: GitHub account बनाउने
1. [github.com](https://github.com) खोल्नुहोस् → **Sign up**।
2. Email, password, username राखेर account बनाउनुहोस्।
3. Username याद राख्नुहोस् (लिङ्कमा चाहिन्छ)।

### चरण २: Public repository बनाउने
1. माथि दायाँतिर **+** → **New repository**।
2. **Repository name:** जस्तै `jyotish-notice`
3. **Public** छान्नुहोस् ⚠️ (Private राख्दा एपले फाइल पढ्न सक्दैन)।
4. **Add a README file** मा ✅ टिक लगाउनुहोस्।
5. **Create repository** थिच्नुहोस्।

> 💡 गोप्य कोड/डाटा भएको repo सँग यसलाई नमिसाउनुहोस्। सूचनाका लागि यो छुट्टै public repo हो।

### चरण ३: पहिलो `notice.json` बनाउने
1. Repo भित्र **Add file → Create new file**।
2. फाइलको नाम: `notice.json`
3. भित्र यो लेख्नुहोस्:

```json
{
  "enabled": false,
  "items": [
    { "title": "नमस्कार", "text": "यो परीक्षण सूचना हो।" }
  ]
}
```

4. तल **Commit changes…** → **Commit changes** थिच्नुहोस्।

### चरण ४: `notice.json` को Raw लिङ्क निकाल्ने
1. Repo मा `notice.json` थिच्नुहोस्।
2. माथि दायाँ **Raw** बटन थिच्नुहोस्।
3. Browser को address bar को लिङ्क कपी गर्नुहोस्। यस्तो देखिन्छ:

```
https://raw.githubusercontent.com/तपाईंको-username/jyotish-notice/main/notice.json
```

> ⚠️ `github.com/.../blob/...` वाला लिङ्क **चल्दैन**। `raw.githubusercontent.com` वाला नै चाहिन्छ।
> ⚠️ Default branch `master` छ भने लिङ्कमा `main` को सट्टा `master` हुन्छ। Raw थिच्दा देखिएको लिङ्क जस्ताको तस्तै लिनुहोस्।

### चरण ५: एपमा लिङ्क राख्ने (एकपटक मात्र)
1. Caps मा `NoticeBoard.kt` खोल्नुहोस्।
2. यो लाइन खोज्नुहोस् र आफ्नो लिङ्क राख्नुहोस्:

```kotlin
const val REMOTE_URL: String = "https://raw.githubusercontent.com/तपाईंको-username/jyotish-notice/main/notice.json"
```

3. `LOCAL_ENABLED` `false` नै रहन दिनुहोस्।
4. एप build गरेर नयाँ संस्करण निकाल्नुहोस् र phone मा राख्नुहोस्।

✅ यति गरेपछि भविष्यमा एपमा केही छुनु पर्दैन।

## भाग २ — नियमित प्रयोग (हरेक पटक)

### सूचना बदल्ने / ON गर्ने
1. GitHub मा आफ्नो repo खोल्नुहोस् → `notice.json` थिच्नुहोस्।
2. माथि दायाँ ✏️ (**Edit**) थिच्नुहोस्।
3. सामग्री बदल्नुहोस् (भाग ३ का नमूना हेर्नुहोस्)।
4. **Commit changes** → **Commit changes** थिच्नुहोस्।
5. केही मिनेटमा (करिब ५–१०) एपमा देखिन्छ।

### सबै सूचना बन्द (OFF) गर्ने
```json
{ "enabled": false, "items": [] }
```
Commit गर्नुहोस्। एपमा बक्स पूरै गायब हुन्छ (ठाउँ पनि लिँदैन)।

### एउटा सूचना मात्र लुकाउने (मेटाउनु नपर्ने)
त्यो item मा `"enabled": false` थप्नुहोस्। बाँकी सूचना देखिइरहन्छन्।

## भाग ३ — JSON का नमूना (कपी गरेर प्रयोग गर्नुहोस्)

> `title`, `text`, `image`, `pdf`, `link`, `enabled`, `from`, `until` सबै **ऐच्छिक** छन्। जुन चाहिएन त्यो नलेख्नुहोस्।

### १) केवल text
```json
{
  "enabled": true,
  "items": [
    { "title": "सूचना", "text": "आज साँझ ७ बजे कार्यक्रम हुनेछ।" }
  ]
}
```

### २) केवल तस्बिर
```json
{
  "enabled": true,
  "items": [
    { "image": "https://raw.githubusercontent.com/USERNAME/jyotish-notice/main/poster.jpg" }
  ]
}
```

### ३) केवल PDF
```json
{
  "enabled": true,
  "items": [
    {
      "title": "फारम",
      "pdf": "https://raw.githubusercontent.com/USERNAME/jyotish-notice/main/form.pdf"
    }
  ]
}
```

### ४) text + तस्बिर + PDF + लिङ्क (एउटै कार्डमा)
```json
{
  "enabled": true,
  "items": [
    {
      "title": "विशेष सूचना",
      "text": "विवरण यहाँ लेख्नुहोस्।",
      "image": "https://raw.githubusercontent.com/USERNAME/jyotish-notice/main/poster.jpg",
      "pdf": "https://raw.githubusercontent.com/USERNAME/jyotish-notice/main/form.pdf",
      "link": "https://example.com"
    }
  ]
}
```

### ५) धेरै सूचना एकसाथ
```json
{
  "enabled": true,
  "items": [
    { "title": "पहिलो सूचना", "text": "..." },
    { "title": "दोस्रो सूचना", "image": "https://raw.githubusercontent.com/USERNAME/jyotish-notice/main/b.jpg" }
  ]
}
```

## भाग ४ — ⏳ म्याद (expiry) तोक्ने

### मूल नियम
| फिल्ड | अर्थ | उदाहरण (BS) | उदाहरण (AD) |
|---|---|---|---|
| `from` | यो मितिदेखि देखाउने (त्यो दिनको सुरुबाट) | `"2083-07-25"` | `"2026-11-10"` |
| `until` | यो मितिसम्म देखाउने (त्यो दिन रातिसम्म) | `"2083-08-05"` | `"2026-11-20"` |
| समयसहित | त्यो मिनेटसम्म (२४ घण्टे) | `"2083-08-05 18:30"` | `"2026-11-20 18:30"` |

### 📆 बि.सं. (BS) कि AD — एपले कसरी छुट्याउँछ
- **साल `2070` वा सोभन्दा ठूलो** → बि.सं. (BS) मानिन्छ। जस्तै `2083-08-05`
- **साल `2070` भन्दा सानो** → अङ्ग्रेजी (AD) मानिन्छ। जस्तै `2026-11-20`
- निश्चित गर्न चाहे अगाडि `BS` वा `AD` लेख्न मिल्छ:
  - `"BS 2083-08-05"`
  - `"AD 2026-11-20"`
  - `"BS 2083-08-05 18:30"`
- नेपाली अङ्क पनि चल्छ: `"२०८३-०८-०५"`।
- विभाजक `-` , `/` , `.` जुनसुकै: `2083/08/05`, `2083.08.05`।
- महिना १–१२ र दिन त्यो महिनाको वास्तविक दिनभित्र हुनुपर्छ (जस्तै कार्तिक २०८३ मा ३० दिन भए `31` गलत)। बि.सं. को दिनसङ्ख्या एपको आफ्नै पात्रो तालिकाबाट जाँचिन्छ।

> 💡 दैनिक प्रयोगमा **`BS` अगाडि लेख्नु सबैभन्दा सुरक्षित**, ग्रेगोरियन र बि.सं. नमिसिने भएकाले।

### अन्य नियम
- मिति मात्र लेखे `until` को दिनभरि देखिन्छ, र `from` को दिनको सुरुदेखि।
- समय युजरको मोबाइलको घडी अनुसार हुन्छ।
- म्याद नाघेपछि एपले आफैं लुकाउँछ। तपाईंले JSON बदल्नु पर्दैन। सबै सूचनाको म्याद नाघे बक्सै गायब हुन्छ।
- एप खुलेकै बेला म्याद नाघे अर्को पटक एपमा फर्किँदा (वा रिफ्रेस हुँदा) हट्छ।
- मिति गलत ढाँचामा वा अमान्य (जस्तै `2083-13-40`) लेखे त्यो सर्त बेवास्ता हुन्छ, अर्थात् म्याद नलाग्ने (सूचना सधैं देखिने)।

### नमूना ६) एउटा सूचनाको म्याद (BS)
```json
{
  "enabled": true,
  "items": [
    {
      "title": "तिहार शुभकामना",
      "text": "दीपावलीको हार्दिक शुभकामना 🙏",
      "from": "BS 2083-07-20",
      "until": "BS 2083-07-27"
    }
  ]
}
```

### नमूना ६क) AD मितिमा म्याद
```json
{
  "enabled": true,
  "items": [
    { "title": "सूचना", "text": "...", "from": "AD 2026-11-10", "until": "AD 2026-11-20" }
  ]
}
```

### नमूना ७) समय पनि तोकेर (BS)
```json
{
  "enabled": true,
  "items": [
    {
      "title": "प्रत्यक्ष प्रसारण",
      "text": "आज साँझ ७ बजे फेसबुकमा।",
      "from": "BS 2083-07-25 09:00",
      "until": "BS 2083-07-25 21:00"
    }
  ]
}
```

### नमूना ८) धेरै सूचना, हरेकको आफ्नै म्याद
```json
{
  "enabled": true,
  "items": [
    { "title": "सधैं देखिने", "text": "यसमा म्याद छैन।" },
    { "title": "मंसिरमा मात्र", "text": "...", "from": "BS 2083-08-01", "until": "BS 2083-08-30" },
    { "title": "लुकाइएको", "text": "पछि चाहिएला", "enabled": false }
  ]
}
```

### नमूना ९) पूरै बक्सलाई म्याद (बाहिरी तहमा, BS)
```json
{
  "enabled": true,
  "from": "BS 2083-07-25",
  "until": "BS 2083-07-30",
  "items": [
    { "title": "सूचना १", "text": "..." },
    { "title": "सूचना २", "text": "..." }
  ]
}
```

## भाग ५ — तस्बिर र PDF GitHub मा राख्ने

### फाइल अपलोड
1. Repo को मुख्य पृष्ठमा **Add file → Upload files**।
2. तस्बिर (`poster.jpg`) वा PDF (`form.pdf`) तान्नुहोस् वा छान्नुहोस्।
3. **Commit changes** थिच्नुहोस्।

### फाइलको Raw लिङ्क
1. Repo मा फाइल थिच्नुहोस्।
2. **Raw** (वा PDF/तस्बिरमा **Download raw file**) थिच्नुहोस्।
3. Address bar को लिङ्क कपी गरेर `notice.json` मा `image` वा `pdf` मा राख्नुहोस्।

लिङ्कको ढाँचा सधैं यही हुन्छ:
```
https://raw.githubusercontent.com/USERNAME/REPO/main/फाइलको-नाम
```

### फाइलको नियम
| कुरा | सुझाव |
|---|---|
| तस्बिरको प्रकार | `jpg`, `png`, `webp` |
| तस्बिरको साइज | १ MB भित्र राख्दा राम्रो |
| PDF | खोल्दा हरेकपटक डाउनलोड हुन्छ, त्यसैले साना राख्नुहोस् |
| फाइलको नाम | अङ्ग्रेजी अक्षर र अङ्क, space नराख्नुहोस् (`poster1.jpg`) |
| वेब अपलोड सीमा | प्रति फाइल २५ MB सम्म |

## भाग ६ — सामान्य गल्ती र समाधान

| समस्या | कारण | समाधान |
|---|---|---|
| सूचना देखिँदैन | `"enabled": false` छ | `true` गर्नुहोस् |
| सूचना देखिँदैन (म्याद राखेको) | `from` अझै आएको छैन वा `until` नाघिसक्यो | मिति जाँच्नुहोस् |
| म्याद लागेन | मिति गलत ढाँचामा (जस्तै `05-08-2083`) वा अमान्य दिन | `BS 2083-08-05` (साल पहिले) राख्नुहोस्; गलत भए एपले म्याद बेवास्ता गर्छ |
| परिवर्तन तुरुन्त देखिँदैन | GitHub र एपले करिब ५–५ मिनेट cache गर्छन् | १०–१५ मिनेट पर्खनुहोस्, एप फेरि खोल्नुहोस् |
| केही पनि बदलिँदैन | JSON मा गल्ती छ (एपले पुरानै राख्छ) | [jsonlint.com](https://jsonlint.com) मा जाँच्नुहोस् |
| तस्बिर देखिँदैन | `blob` लिङ्क राखिएको, वा repo private | `raw.githubusercontent.com` लिङ्क र public repo |
| पुरानै तस्बिर देखिन्छ | एपले तस्बिर मेमोरीमा राख्छ | तस्बिरको नाम बदल्नुहोस् (`poster2.jpg`) |
| PDF खुल्दैन | लिङ्क गलत वा फाइल बिग्रेको | Raw लिङ्क browser मा खोलेर हेर्नुहोस् |

### JSON लेख्दा याद राख्ने
- ✅ सधैं सिधा उद्धरण `"` प्रयोग गर्नुहोस् (मोबाइल keyboard को `“ ”` होइन)।
- ✅ अन्तिम item पछि अल्पविराम `,` नराख्नुहोस्।
- ✅ हरेक `{` को `}` र हरेक `[` को `]` हुनुपर्छ।
- ✅ नेपाली अक्षर सामान्य रूपमा लेख्न मिल्छ।
- ✅ text मा नयाँ लाइन चाहिए `\n` लेख्नुहोस् (जस्तै `"text": "पहिलो\nदोस्रो"`)।
- ✅ `enabled` मा `true` / `false` उद्धरणबिना लेख्नुहोस्; मिति भने उद्धरणभित्र।
- ✅ मितिमा साल पहिले: `2083-08-05` (दिन-महिना-साल होइन)।
